# 无尽模式实施计划

状态：第一至第八阶段代码、自动回归和首轮经济调参已完成；首页无尽入口已开放正式付费挑战，已有挑战优先续局，不重复扣费。测试与正式存档独立。规则版本：endless-v1。自动对局结果不代表真人体验已经平衡，后续依据长局试玩反馈继续调整。

## 已确定的首版规则

- 四个正式主题 × 三个难度，每项至少胜利一次，共 12 项通关后解锁。
- 每次入场准确扣除 100 外部金币；余额不足不能进入。玩家初始 12 HP。
- 新挑战赠送 70 补给金币，背包为空；进入后先购买，点击“准备好了 · 开始牌局”才开始第一轮被动和发牌。不可消耗外部库存或追加外部金币。装备的纯视觉特效保留。
- 正式 NPC 每击败一名获得 25 局内金币、沿用现有击杀回血 1 HP。
- 正式击败数达到 1、3、5、7……时获得购买机会，在轮末开放。
- 每次购买机会每种道具库存 1，每次最多购买 2 件；背包总容量 4 件。
- 取消整局道具使用次数限制和圣盾整局一次限制；圣盾生效时不能重叠使用。原有使用阶段和代价不变。
- 当前基础价格：命运啤酒 20、听天由命 15、共鸣号角 30、圣盾 45、共鸣骰 25（第八阶段号角/圣盾由 35/55 下调，之后新增共鸣骰）。
- 阶段 s = floor(K / 5)。新 NPC 生命 = 原困难生命 + s；道具价格 = 基础价 + 5s。
- 下一轮额外敌方攻击伤害 = floor(K / 10)。不计入共鸣牌型倍率，不影响原被动阈值。
- 难度快照在下一轮准备时确定，同轮多次击杀不会令后续攻击突然升级。
- 灵魂救赎整次挑战只能使用一次，进入新轮及补位不重置。
- 英灵沿用 1 HP、每位女武神最多召唤两次，不给金币、击杀回血、商店进度或共鸣奖励；单独记录清除数。
- 玩家正式共鸣攻击实际造成伤害时，按牌型倍率累计 R：2、3、4、8 等。普通、平分、全闪避不计；挡刀一次攻击仅计一次。
- 结算：可结算余额 + 10K + min(2R, 10K)。可结算余额 = max(0, 25K - max(0, 局内消费 - 初始补给))。补给优先消费，剩余补给不提现；当前金币包含补给，结算获得仅包含可结算余额及奖励。净收益额外扣除已支付的入场费 100。
- 战败和主动结束采用同一结算规则，未用道具不退钱、不带出。

## 第一阶段：独立模式配置、通关记录与入场

### 开局难度优化补充

新挑战的 70 补给金币可购买圣盾 45 + 命运啤酒 20，余下 5 继续留在局内。开局商店每种库存 1、最多买 2、背包容量 4，可跳过；不占用奇数击杀商店机会。啤酒文案明确满血不能使用，受伤后应在看牌或听天由命前使用。

补给额度、消费、商店库存和开局完成状态随牌堆随机状态保存，刷新不重新赠送、不重复施法。旧续局和旧已付款预约缺少补给字段时按 0 恢复，不追赠、不插入新商店。开局直接结束结算 0，不退入场费；剩余补给和道具不带出。

参数在 src/game/endless/EndlessConfig.ts 的 startingSupplyCoins。70 是待真人试玩验证的初始值。自动策略对比见 endless-opening-supply-balance.json，不能替代真人体验验证。

验证：105 项自动回归通过，构建通过。补充覆盖开局未发牌/未施法、提前看牌阻断、购物库存和随机状态恢复、写入失败回滚、首个奇数击杀商店、旧预约与旧快照兼容、补给优先消费和零击杀零结算。固定种子共 2,000 次自动对局未触及轮数上限；防守购买策略的首次击败前失败率由 29.2% 降至 14.4%，击败数中位数由 2 提升至 3，攻击购买策略并未表现出同样改善。

涉及：src/game/progress.ts、src/game/economy.ts、src/game/types/economy.ts、src/scenes/TableSelectScene.ts。

新增无尽配置与状态模块（建议 src/game/endless/ 下放置 EndlessConfig、EndlessState、EndlessRules、EndlessSession），集中维护价格、成长、结算纯函数。模式字段显式区分 story / formal / endless，背景主题不承担玩法判断。

增加正式通关记录 winsByThemeAndDifficulty，只记录实际获胜的对应难度。旧 winsByTheme 保留原含义，缺失的新记录初始化为空，不能推断旧玩家通关了全部难度。测试存档可以显式填满 12 项。

验收：11 项锁定 / 12 项解锁；金币 99 不可进入 / 100 可进入；连点只扣一次；旧存档可正常读取。

## 第三阶段：无尽战斗循环、召唤与补位

涉及：src/game/battle.ts、src/game/engine/BattleEvents.ts、src/game/engine/BattleEngine.ts；新增 EndlessRoster。

固定索引 0=左、1=上、2=右。三个独立随机袋：

- 左：goblin / viking_warrior / swordsman / shogun_samurai。
- 上：gambler / rune_shaman / songstress / ninja。
- 右：werewolf / valkyrie / taoist / oiran。

初次分别抽取；袋抽完重新洗牌，尽量不连续重复上次角色。NPC 最终死亡后空位保留到下一轮，不在当前攻击序列中即时换人。所有状态由统一角色创建函数初始化，存活 NPC 的生命及永久状态保留。

轮末：攻击及救赎结束 → 最终击杀记账 → 有机会则购物 → 下一轮准备 → 女武神优先召唤 → 剩余空位补人 → 难度快照 → 新轮被动 → 发牌。女武神保留原低血阈值、最多两次且只允许一名存活英灵；召唤可占用左或上空位，不受正式座位池约束。英灵被清除后位置仍按原池补人。

无尽全灭敌人不进入 victory。玩家救赎资格不能因同轮敌人全部死亡而被错误取消。女武神召唤只能在轮准备链路执行一次，避免与原 prepareEnemyRoundStartPassives 重复。

验收：单杀 / 三杀补位、无击杀不补、全灭继续、女武神召唤优先、上限两次、女武神自己死亡时不召唤、英灵清除后补人、双方同时死亡的救赎与结算顺序。

## 第四阶段：战斗记账与难度成长

新增逻辑事件 npc-defeated、resonance-scored、endless-stage-changed，事件包含实例及唯一动作编号。记录不得依赖 consumePresentationEvents、动画 onHit 或 render，避免渲染重复与刷新时重复计分。

每个 NPC 实例最终死亡登记一次。每次玩家成功伤害事件最多登记一次共鸣；侠客转移伤害是同一次攻击，不重复加分。生命实际损失、护盾、闪避、召唤属性应在规则层提供明确结果。

轮末累计购物机会数：比较前后 floor((K+1)/2)，不是只检查最终 K 是否奇数。购买价格按本次商店开放时的 K 固定，多机会共享窗口但每次独立库存。显示下一轮成长预告，不突然改变本轮攻击。

验收：回血不会重新计击杀；死亡动画重播不加分；攻击多目标按各成功比牌计分；挡刀一次；英灵、普通、平分、全闪避为零；从 0 到 3 产生两次购物机会；跨 5/10 阈值下一轮才成长。
