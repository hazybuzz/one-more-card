# 《再来一张》图标美术规范

版本：1.0  
适用范围：玩家技能、角色被动、战斗道具、特效道具、状态效果

## 1. 风格定位

图标统一采用：

> 暗黑奇幻像素徽记，以清晰剪影和鲜明动作表达功能，使用 5-7 种实体颜色。

图标不追求角色立绘级别的细节。它首先是战斗信息，其次才是装饰。

玩家在不知道名称的情况下，应能从图形大致判断它属于以下哪一种行为：

- 攻击或增伤
- 防御或减伤
- 治疗或复活
- 抽牌、换牌或改牌
- 召唤
- 控制或侦察

## 2. 核心原则

### 2.1 一眼识别

- 每个图标只表现一个主要概念。
- 主体占画布面积的 65%-78%。
- 使用一个主轮廓和最多两个辅助元素。
- 优先表现动作结果，不表现完整故事场景。
- 在 48px 实际显示尺寸下，主体仍必须清楚。

错误示例：人物、酒馆、牌桌和火焰同时出现。  
正确示例：一只号角向外喷出两道红色声浪。

### 2.2 轮廓优先

- 将图标转成纯黑剪影后，仍应与其他图标有明显区别。
- 主体外轮廓使用 1-3 个逻辑像素宽的深色描边。
- 避免大量细线、碎屑、细小文字和密集装饰。
- 不依赖颜色作为唯一信息来源。

### 2.3 功能优先于写实

- 允许夸大武器、盾牌、药瓶、卡牌和灵魂等关键物体。
- 允许使用不符合真实比例的动作线和魔法符号。
- 材质只保留最容易辨认的特征，不描绘复杂纹理。

## 3. 像素与尺寸

### 3.1 标准尺寸

| 用途 | 尺寸 | 说明 |
| --- | ---: | --- |
| 逻辑设计网格 | 64×64 | 所有轮廓和细节以此尺寸判断 |
| 游戏资源 | 128×128 PNG | 从逻辑网格按最近邻放大 |
| 可选创作母版 | 256×256 PNG | 仅用于生成和修改，最终必须重新像素化 |
| 游戏实际显示 | 40-56px | 必须在该尺寸验收 |

### 3.2 像素规则

- 禁止平滑渐变和照片纹理。
- 禁止模糊、景深和柔边笔刷。
- 斜线应形成可读的像素阶梯。
- 资源缩放必须使用 nearest-neighbor。
- 透明背景不计入颜色数量。
- 半透明发光不画进资源，由 Phaser 在运行时生成。

## 4. 色彩规范

### 4.1 色数限制

每个图标使用 5-7 种不透明颜色，透明背景除外。

推荐结构：

1. 最深轮廓色
2. 阴影色
3. 主体中间色
4. 主体亮色
5. 核心强调色
6. 可选强调色
7. 可选最高光色

同一色相的明暗变化也分别计算为一种颜色。

### 4.2 共用基础色

所有图标优先从以下基础关系中取色，不要求每张图使用完全相同的色值：

| 角色 | 建议色值 | 用途 |
| --- | --- | --- |
| 深轮廓 | `#15131a` | 外轮廓、最深缝隙 |
| 暗部 | `#2b2530` | 阴影、背光面 |
| 暖亮部 | `#d7c49a` | 金属、骨骼、纸牌亮面 |
| 最高光 | `#f1e4bf` | 小面积视觉焦点 |

剩余 1-3 色根据功能选择。

### 4.3 功能强调色

| 功能 | 推荐强调色 | 典型元素 |
| --- | --- | --- |
| 共鸣、命运 | 旧金、靛蓝 | 符文、命运线、牌 |
| 攻击、增伤 | 暗红、橙红 | 刀痕、火星、声浪 |
| 防御、护盾 | 银蓝、青蓝 | 盾牌、屏障、冰晶 |
| 治疗、复活 | 祖母绿、暖金 | 心火、灵魂、嫩芽 |
| 侦察、控制 | 紫色、冷青 | 眼睛、雾、锁链 |

颜色只负责强化功能，不能替代主体轮廓。

## 5. 构图规范

### 5.1 安全区

- 主体必须完整位于画布中央 80% 的安全区内。
- 武器、光线和烟雾不得贴边或被截断。
- 图标四周至少保留 8 个逻辑像素的透明空间。
- 视觉重心可以轻微偏移，但不能让图标在圆形槽位中显得歪斜。

### 5.2 视角

- 实体物品默认使用轻微 3/4 视角。
- 徽记、眼睛、灵魂和法阵默认使用正视角。
- 同一系列中的同类物品保持一致视角。

### 5.3 动作表达

使用 1-2 个大动作符号，不使用大量小粒子：

- 增伤：向外扩张的尖锐线条
- 防御：包围主体的弧线或盾面
- 治疗：向上聚合的光点或心火
- 换牌：两张牌之间的明确交换箭头
- 召唤：从法阵或裂隙中出现的主体
- 被动触发：稳定的中心徽记加一次外扩波纹

## 6. 类别差异

所有图片保持同一画风，但用构图区分类别。

### 6.1 玩家主动技能

- 强调动作和方向。
- 允许使用牌、命运线、法阵和手势。
- 主体通常从左下向右上运动，形成主动感。

### 6.2 角色被动技能

- 使用稳定、居中的徽章式构图。
- 优先选择角色代表物：号角、月牙、符文、酒杯、武器。
- 不描绘角色头像，避免与人物立绘竞争。

### 6.3 战斗道具

- 表现一个完整、可触摸的物品。
- 轮廓应像背包中的实物，不使用抽象徽记代替。
- 同系列瓶子、符纸和护具保持相同比例与视角。

### 6.4 特效道具

- 以武器或法术核心为主体。
- 可以比普通道具更华丽，但仍遵守 5-7 色和主体数量限制。
- 不在静态图标中描绘完整攻击动画。

### 6.5 状态效果

- 比技能图标更简洁，最多一个主体和一个辅助符号。
- 必须适合缩小到 24-32px。
- 数值和持续回合由 UI 文本显示，不画进图标。

## 7. 图片中禁止包含的内容

- 圆形槽位、方形面板或技能边框
- 冷却数字、使用次数和价格
- 中文、英文或其他文字
- UI 阴影、按钮高光和悬浮边框
- 大面积外发光
- 复杂背景场景
- 超过两个同等重要的主体
- 无法在 48px 下辨认的纹理

上述状态均由 Phaser UI 统一处理。

## 8. 运行时表现分工

静态图标只负责“是什么”，运行时效果负责“现在是什么状态”。

| 状态 | Phaser 表现 |
| --- | --- |
| 可使用 | 正常色彩，轻微呼吸光 |
| 鼠标悬浮 | 边框提亮，图标轻微放大 |
| 冷却中 | 降低饱和度，显示冷却数字 |
| 条件不足 | 灰色遮罩，保留清楚轮廓 |
| 已触发 | 短暂闪光、波纹或震动 |
| 已耗尽 | 深灰处理，停止呼吸光 |

不要为每种状态制作一张独立图片。

## 9. 文件结构与命名

```text
public/image/icons/
  skills/
    resonance-shift.png
    resonance-summon.png
  passives/
    soul-redeem.png
    war-horn.png
  items/
    fate-beer.png
    fate-horn.png
  cosmetics/
    thors-hammer.png
    sakura-slash.png
  statuses/
    attack-up.png
    shielded.png
```

命名规则：

- 全部使用小写英文和 kebab-case。
- 文件名使用稳定 ID，不使用中文名称。
- 不在文件名中加入价格、等级或当前数值。
- 修订稿使用工作目录保存；正式资源不使用 `final-v2-new` 等名称。

## 10. AI 生成基础描述

生成单个图标时，在具体主体描述后追加以下约束：

```text
暗黑奇幻像素游戏图标，64×64 逻辑像素密度，透明背景。
只表现一个清晰主体和最多两个辅助元素，主体占画布约 70%。
严格使用 5-7 种不透明颜色，深色粗轮廓，清晰像素阶梯，
高对比度剪影，少量中世纪符文或磨损细节，缩小到 48px 仍能一眼识别。
无文字、无数字、无UI边框、无圆形底板、无渐变、无模糊、无大面积外发光、无复杂背景。
```

AI 结果不能直接视为完成稿，必须经过以下处理：

1. 裁切并统一透明边距。
2. 量化到 5-7 色。
3. 清理孤立像素和模糊边缘。
4. 最近邻缩放到 128×128。
5. 放入实际游戏槽位检查。

## 11. 第一批风格样片

在批量生产前，先制作以下五张，覆盖不同类别：

| 图标 | 类别 | 核心画面 |
| --- | --- | --- |
| 共鸣转换 | 主动技能 | 两张不同花色的牌被金色命运线连接并改变 |
| 共鸣召唤 | 主动技能 | 一张牌从靛蓝符文阵中升起 |
| 灵魂救赎 | 玩家被动 | 破碎灵魂重新点燃金色心火 |
| 战争号角 | NPC 被动 | 旧铜号角喷出两道红色声浪 |
| 命运啤酒 | 战斗道具 | 深色酒瓶中升起绿色生命光 |

五张样片在实际 UI 中通过后，才能以其中最稳定的一张作为后续生成参考图。

## 12. 验收清单

每个图标提交前逐项检查：

- [ ] 透明背景，无烘焙槽位和边框
- [ ] 使用 5-7 种实体颜色
- [ ] 只有一个主要概念
- [ ] 主体占比约 65%-78%
- [ ] 四周安全区完整，无裁切
- [ ] 纯黑剪影仍能与其他图标区分
- [ ] 48px 下能辨认主体
- [ ] 灰度状态下仍能辨认功能
- [ ] 无文字、数字和价格
- [ ] 无渐变、模糊和大面积外发光
- [ ] 与同类别图标的视角和像素密度一致
- [ ] 文件名和目录符合规范
